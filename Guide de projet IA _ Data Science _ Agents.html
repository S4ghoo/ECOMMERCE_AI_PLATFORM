Guide de projet : plateforme de données, ML, RAG et agents IA

Un guide pas à pas pour réaliser un projet de portfolio complet, destiné aux candidatures d'ingénieur(e) IA et data scientist.

1. Présentation du sujet

Vous construisez une plateforme intelligente pour un e-commerce, de la donnée brute jusqu'à un copilote d'agents IA déployé en ligne.

Elle comporte cinq couches :

  1. Données : pipeline d'ingestion, nettoyage et stockage.
  2. Machine learning : prédiction de l'insatisfaction client, segmentation, recommandation.
  3. NLP / RAG : assistant qui répond aux questions à partir des avis clients et de la documentation.
  4. Agents IA : un orchestrateur et des agents spécialisés qui utilisent des outils (SQL, modèles ML, RAG) pour accomplir des tâches.
  5. Production : API, Docker, CI/CD, suivi des expériences, monitoring.

2. Objectifs

Objectif métier : aider une équipe e-commerce à repérer les clients à risque, comprendre leurs motifs d'insatisfaction et agir (recommandation, message, rapport).

Objectifs de carrière : démontrer sur un seul projet les compétences suivantes :

  • Python, SQL, statistiques, visualisation
  • ML supervisé et non supervisé, évaluation rigoureuse
  • Embeddings, systèmes de recommandation
  • LLM, RAG, agents, MCP
  • MLOps : MLflow, DVC, Docker, CI/CD, monitoring

Résultat attendu : un dépôt GitHub propre, une démo en ligne et un README avec des résultats chiffrés.

3. Datasets

Dataset principal (recommandé) : Olist Brazilian E-Commerce

  • https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce
  • Environ 100 000 commandes, plusieurs tables (commandes, clients, produits, vendeurs, paiements, livraisons, avis). C'est idéal pour le SQL et les jointures.
  • Attention : très peu de clients rachètent, donc la cible « churn » n'est pas adaptée. Utilisez plutôt l'insatisfaction (note d'avis ≤ 2) ou le retard de livraison.

Alternatives et compléments

4. Outils à installer

Python 3.11+, Git/GitHub, VS Code, Docker, PostgreSQL, Jupyter. Bibliothèques : pandas, scikit-learn, XGBoost/LightGBM, Optuna, SHAP, MLflow, DVC, FastAPI, Pydantic, LangGraph (ou autre framework d'agents), une base vectorielle (Chroma, FAISS ou pgvector), Streamlit, Evidently, Langfuse.

5. Étapes à suivre

Phase 0 : Préparation (2 jours)

  • Créez le dépôt GitHub avec cette structure : data/, notebooks/, src/, api/, agents/, tests/, docs/.
  • Créez un environnement virtuel et un fichier requirements.txt.
  • Rédigez dès maintenant un README provisoire : problème, objectif, plan.
  • Livrable : dépôt initialisé.

Phase 1 : Ingestion et pipeline de données (semaine 1)

  1. Téléchargez Olist et versionnez les données brutes avec DVC (sans les pousser sur Git).
  2. Chargez les tables dans PostgreSQL et définissez les clés.
  3. Écrivez des scripts de nettoyage : valeurs manquantes, doublons, types, dates.
  4. Ajoutez des contrôles de qualité (Great Expectations ou tests Pandera).
  5. Orchestrez le tout avec Airflow ou Prefect.
  • Livrable : pipeline reproductible en une commande.

Phase 2 : Analyse exploratoire (semaine 2)

  1. Posez 5 à 10 questions métier (délais de livraison, catégories, satisfaction par région).
  2. Réalisez des visualisations claires (Matplotlib, Plotly).
  3. Construisez la segmentation RFM et un clustering K-Means ; interprétez chaque segment.
  4. Résumez vos découvertes en un court texte.
  • Livrable : notebook EDA commenté + résumé des conclusions.

Phase 3 : Machine learning supervisé (semaines 3-4)

  1. Définissez la cible (ex. insatisfait = note ≤ 2) et évitez toute fuite de données (n'utilisez que l'information disponible au moment de la prédiction).
  2. Créez des variables : délai estimé/réel, prix, poids, distance vendeur-client, catégorie.
  3. Établissez un modèle de base (régression logistique) puis XGBoost ou LightGBM.
  4. Validez par validation croisée ; comparez avec AUC, précision/rappel, F1 ; gérez le déséquilibre des classes.
  5. Optimisez avec Optuna et suivez chaque essai dans MLflow.
  6. Expliquez le modèle avec SHAP.
  • Livrable : modèle enregistré dans MLflow + tableau comparatif des modèles.

Phase 4 : Recommandation (semaine 4)

  1. Commencez par une approche simple : produits ou catégories fréquemment achetés ensemble.
  2. Ajoutez une approche par embeddings (descriptions de produits, similarité cosinus).
  3. Si les données Olist sont trop clairsemées, faites cette étape sur Instacart, H&M ou MovieLens et dites-le clairement dans le README.
  4. Mesurez avec Precision@K, Recall@K ou NDCG@K.
  • Livrable : module de recommandation évalué.

Phase 5 : NLP et RAG (semaines 5-6)

  1. Nettoyez les avis clients (langue : portugais ; traduisez ou utilisez un modèle multilingue).
  2. Faites une analyse de sentiment ou une extraction des motifs d'insatisfaction.
  3. Découpez les textes, créez des embeddings et indexez-les dans une base vectorielle.
  4. Construisez la chaîne RAG : recherche, génération avec citation des sources.
  5. Évaluez : jeu de 30 à 50 questions avec réponses attendues, mesure de la fidélité aux sources (Ragas ou LLM-as-judge).
  • Livrable : assistant RAG + rapport d'évaluation.

Phase 6 : Agents IA (semaines 6-7)

  1. Définissez vos outils, chacun avec un schéma d'entrée/sortie validé par Pydantic : run_sql, predict_risk, recommend, search_reviews, draft_message.
  2. Créez un premier agent unique qui utilise ces outils.
  3. Passez à l'architecture multi-agents : orchestrateur, analyste de données, agent documentaire, agent d'action (framework : LangGraph ou équivalent).
  4. Exposez vos outils via un serveur MCP.
  5. Ajoutez une validation humaine avant toute action à impact.
  6. Ajoutez des garde-fous : permissions minimales, requêtes SQL en lecture seule, limites de budget et d'étapes, protection contre l'injection de prompt.
  7. Évaluez sur 30 à 50 scénarios : taux de réussite, nombre d'étapes, coût, latence. Analysez les échecs.
  • Livrable : système d'agents + tableau d'évaluation + analyse des échecs.

Phase 7 : API, conteneurs et CI/CD (semaine 8)

  1. Exposez modèles et agents avec FastAPI (documentation Swagger automatique).
  2. Écrivez des tests avec pytest.
  3. Créez les Dockerfiles et un docker-compose.yml (API, base de données, base vectorielle).
  4. Mettez en place GitHub Actions : lint, tests, build de l'image.
  • Livrable : application démarrable avec docker compose up.

Phase 8 : Déploiement et monitoring (semaines 9-10)

  1. Déployez sur un cloud (AWS, GCP, Azure) ou sur Hugging Face Spaces / Render pour rester gratuit.
  2. Créez une interface Streamlit pour la démo.
  3. Ajoutez le suivi de dérive des données avec Evidently et le traçage des agents avec Langfuse.
  • Livrable : démo en ligne + tableau de bord de suivi.

Phase 9 : Finalisation et valorisation (semaine 10)

  1. Rédigez un README professionnel : contexte, schéma d'architecture, résultats chiffrés, installation, limites, pistes d'amélioration.
  2. Enregistrez une vidéo de démonstration de 3 minutes.
  3. Publiez un article (LinkedIn, Medium) qui raconte vos choix techniques.
  4. Ajoutez le projet au CV et au profil LinkedIn.

6. Points de contrôle qualité

  • Le projet se lance avec une seule commande.
  • Aucune fuite de données dans les modèles.
  • Chaque modèle est comparé à un modèle de base.
  • Les résultats sont chiffrés et honnêtes, limites comprises.
  • Les agents sont évalués sur des scénarios reproductibles.
  • Aucune clé d'API dans le dépôt (utilisez un fichier .env ignoré par Git).
  • La démo est accessible par un lien.

7. Formulation pour le CV

Conception et déploiement d'une plateforme e-commerce intelligente : pipeline de données (Airflow, PostgreSQL, DVC), modèles prédictifs (XGBoost, SHAP, MLflow), système de recommandation, assistant RAG et copilote multi-agents (LangGraph, MCP) avec validation humaine, évaluation automatisée, API FastAPI dockerisée, CI/CD et monitoring (Evidently, Langfuse).

8. Si le temps manque

Version réduite, tout aussi crédible : phases 1, 2, 3, 5, 7 et 9, puis ajoutez un agent unique avec deux outils. Mieux vaut un projet plus petit, complet et bien documenté qu'un projet immense inachevé.
